#### Comparación de Librerías para: Notificaciones "Toast"

**Problema:** Necesitamos un sistema de notificaciones no intrusivas (conocidas como "toasts" o "snackbars") para proporcionar feedback inmediato al usuario tras realizar una acción, como guardar un formulario, encontrar un error en una petición API o confirmar una operación.

| Criterio                       | [![Toast Library - React Hot Toast](https://img.shields.io/badge/React%20Hot%20Toast-FF3366?style=for-the-badge&logoColor=white)](https://react-hot-toast.com) | [![Toast Library - React Toastify](https://img.shields.io/badge/React%20Toastify-8A2BE2?style=for-the-badge&logoColor=white)](https://fkhadra.github.io/react-toastify) |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Popularidad/Comunidad**      | Extremadamente popular y en rápido crecimiento. Es la opción preferida en muchos proyectos modernos por su simplicidad y elegancia.                                    | El veterano y líder del mercado por mucho tiempo. Comunidad masiva, muy maduro y probado en batalla en miles de aplicaciones.                                                  |
| **API y Experiencia de Dev (DX)** | **Excepcional.** API minimalista, funcional y muy intuitiva. Su manejo de promesas (`toast.promise`) es una característica estrella que simplifica enormemente el código asíncrono. | Muy buena. API imperativa y fácil de usar (`toast.success('...')`). La configuración se centraliza en un componente `<ToastContainer />`, lo que es claro pero añade un ligero boilerplate. |
| **Personalización**            | **Superior y más moderna.** Diseñada para ser "headless". Permite crear toasts completamente personalizadas con cualquier librería de estilos (Tailwind, Styled Components) de forma trivial. | Muy alta, pero a menudo requiere sobreescribir clases CSS, lo que puede ser más engorroso. Ofrece muchos props para configurar apariencia y comportamiento.                         |
| **Tamaño del Paquete (Bundle Size)** | **Muy ligera.** Es significativamente más pequeña, lo que contribuye a un mejor rendimiento de la aplicación.                                                 | Más grande debido a su extenso conjunto de características (barras de progreso, drag-to-dismiss, etc.) que no siempre son necesarias.                                         |
| **Gestión Asíncrona**          | **La mejor en su clase.** La función `toast.promise` gestiona automáticamente los estados de carga, éxito y error de una promesa con una sola línea de código.     | Buena. Se puede actualizar un toast manualmente para reflejar estados de carga, pero requiere más código y gestión manual en comparación.                                      |
| **Veredicto Rápido**           | La opción moderna, ligera y con la mejor experiencia de desarrollador, especialmente para aplicaciones que hacen uso intensivo de operaciones asíncronas.          | La opción robusta, ultra-configurable y llena de funcionalidades. Ideal si necesitas hasta el último detalle de personalización y no te importa el tamaño extra.              |

---

**🏆 Decisión Final:** Se elige **react-hot-toast**.

**Justificación Principal:** Para un proyecto como **UpSkill**, que utiliza un stack moderno con React y TypeScript, `react-hot-toast` es la elección superior. Su principal ventaja es la **experiencia de desarrollador (DX)**, especialmente su API para manejar promesas. En una aplicación que se comunica constantemente con un backend, poder gestionar los estados de carga, éxito y error de las peticiones API con una sola función (`toast.promise`) no solo reduce drásticamente el código repetitivo, sino que también lo hace más legible y menos propenso a errores.
